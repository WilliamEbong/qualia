# Plan

Stack unchanged (Python 3.14, FastAPI, pydantic, sqlite3; React 19 + Vite + TS). No new dependency. Lanes: STORE/migration, ENGINE (pure miner), AI, SERVER/CLI, WEB — all in the main session (schema and OpenAPI owner).

1. **Migration `qualia/store/migrations/003_code_proposals.sql`.**
   - `code_proposals(id, batch_id, mode CHECK draft|refine|evidence, kind CHECK new_code|revise_code, target_code_id → codes, payload_json json_valid, rationale, evidence_json json_valid, actor_type CHECK model|rule, backend, model, cli_version, prompt_hash, codebook_version_id → codebook_versions NULL, created_at)`; CHECK `kind='new_code' OR target_code_id IS NOT NULL`; CHECK model rows carry backend/model/cli_version/prompt_hash. `codebook_version_id` is nullable because inductive drafting can start before any freeze.
   - `code_proposal_decisions(id, proposal_id UNIQUE → code_proposals, decision CHECK accept|reject, actor non-empty, note, applied_json json_valid, code_id → codes, created_at)`; CHECK accept rows carry `code_id`.
   - UPDATE/DELETE abort triggers for both written in this SQL file.
   - `db.py`: `APPEND_ONLY_V1` drives the migration-1 trigger loop; `APPEND_ONLY` = V1 + the two new tables (tests iterate it); `TABLES` gains them.
2. **Store methods (`qualia/store/db.py`).** `record_code_proposals(rows)` (one transaction); `decide_code_proposal(proposal_id, decision, actor, note='', values=None)` under `immediate()`: rejects a decided proposal, merges human `values` over the payload, applies a new code or only the changed fields of a revision through `save_code`, appends the decision with `applied_json` and resulting `code_id`; `code_proposal_evidence()` returns codes, current coding presence, rejected-suggestion excerpts with review notes, coded-segment count and pending signal keys.
3. **Pure miner `qualia/core/proposals.py`** (sealed): `mine(codes, presence, rejections, coded_segments, pending)` → proposal dicts for the three FR003 signals with fixed thresholds (`MIN_REJECTIONS=2`, `MAX_NEW_NEGATIVES=5`, `UNUSED_AFTER=20`, `OVERLAP_JACCARD=0.8`, `OVERLAP_MIN=5`); skips signals whose `(signal, code ids)` key is pending; never duplicates an existing negative example.
4. **AI (`qualia/ai/`).**
   - `schemas.py`: `ProposedCode` (all fields required for strict structured output; `target_code_id: int | None`), `CodeProposalSet` (≤ 12), `CodeProposalResult` (+ usage), `validate_proposals(raw, mode, segments, codes)` raising `ProposalValidationError('proposal N: reason')` for every FR005 rule.
   - `backends/process.py`: `proposal_prompt(segments, schema, context)` — same bounds as `classification_prompt` (≤ 20 segments, ≤ 4,000 chars, byte cap), lead sentence states transcript text is data and examples must be verbatim.
   - `backends/codex_cli.py` / `claude_cli.py`: classification transport generalised to take a prompt builder and result key; `classify` behaviour unchanged; new `propose`. `fake.py`: deterministic `propose` (draft: one new code quoting the first segment's opening words; refine: one wording revision per sent code). `protocol.py` documents `propose`.
   - `qualia/ai/proposals.py`: `PROMPTS` (in-code draft/refine instructions, research-informed), `propose_with_ai(db, project, mode, backend, model, segment_ids, code_ids, focus, registry)` — selects backend via router `_select`, refuses `rules`/`jev`/missing `propose`, checks segments (≤ 20, `max_segment_chars`) or codes (1–2 active, with ≤ 4 accepted and ≤ 4 rejected segments each, at least one), applies `allow_external`, availability, `ledger.reserve(purpose='codebook_proposal')`/`finish`, validates, stores; `propose_from_evidence(db)` runs the miner and stores `actor_type='rule'` rows. Both return `{batch_id, status, backend, model, proposal_ids, errors}` with safe error codes only.
5. **Server** `qualia/server/proposal_routes.py`: POST `codebook/proposals/evidence`, POST `codebook/proposals/ai` (`ProposalInput`), POST `codebook/proposals/{id}/decision` (`ProposalDecisionInput` with optional partial `ProposalValues`, `exclude_unset`). Workspace payload adds `code_proposals` (proposal rows joined to their decision). Regenerate `openapi.json` and `web/src/api/schema.d.ts`.
6. **CLI** `qualia codebook propose|proposals|decide` with clean `BadParameter` errors.
7. **Export**: both tables in every export; text redaction already covers `payload_json`/`evidence_json`/`applied_json` via `TEXT_FIELDS` (`excerpts`, `definition`, `examples_*`, `note`, `rationale`).
8. **Web**: `lib/entities.ts` `Proposal` type (optional on `Workspace`); `lib/proposals.ts` controller (generate evidence/draft/refine, accept via the existing code editor, reject with note, origin map for code cards); `components/Codebook.tsx` Proposals section with cards (field diff, rationale, evidence excerpts with Open segment, provenance details), editor "Accepting proposal #n" mode, read-only demo empty state; `lib/demo.ts` tolerates the missing key.
9. **Docs**: USER-GUIDE §6 subsection + concepts + CLI table; README tour + Decisions; CONTRACTS additive note.

Ponytail: no proposal editing/withdrawal, no per-project thresholds, no cache, no evaluation-metric signals, no batch UI history, no new nav page.
