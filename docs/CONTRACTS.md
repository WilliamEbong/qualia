# Implementation contracts

Frozen at Phase 1; changes require the main session. Source of truth: `qualia/store/migrations/001_initial.sql`, `openapi.json`, `qualia/ai/protocol.py`.

- SQLite row IDs are integers. Segment start/end are offsets into immutable source text; event span_start/span_end are offsets relative to the segment. All API/storage offsets count Unicode code points, end-exclusive. Web converts Recogito UTF-16 selectors explicitly using `web/src/lib/offsets.ts`.
- `Store` is the only database writer. `rows`/`one` are authorizer-enforced read-only. Writes use `add`, `update`, `freeze_codebook`, `review`, `cache_put` and `transaction`; only mutable code/memo/case/attribute records can update. Review creates a new event plus feedback atomically.
- Frozen snapshot_json is a JSON array of code records. A coding event must refer to a code present in that frozen snapshot. Model events require backend, model, CLI version and prompt hash. Accepted model events retain model details but identify the human reviewer.
- `/api/projects` GET/POST lists/creates slugs; `/api/projects/{slug}` GET is the typed workspace snapshot. The snapshot returns all entity arrays named in api_models.Workspace, plus routing and pipeline_version. Main adds typed mutation endpoints during their feature phase and regenerates OpenAPI.
- Every `/api/` call carries `X-Qualia-Token`; HTML bootstrap meta is read into browser memory. Browser client never stores the token persistently. Foreign hosts/origins rejected. External assets unavailable by CSP.
- Backend classify(segments, schema, context) receives immutable text records `{id: string, text: string}`; context includes frozen `codebook` array, `model`, `prompt`, bounded `max_output_tokens`. Returns `{predictions: [{segment_id: string, codes: [{code_id: integer, score: number, rationale: string, span_start: integer, span_end: integer}]}], input_tokens: integer, output_tokens: integer, cli_version: string}`. Prediction validation must reject unknown/missing/duplicate segments and unknown codes or out-of-range spans. Evaluation predictions do not enter coding_events.
- External backends declare `external=True`; availability never sends research text. Router owns policy and admission; ledger.py is the sole usage/egress write coordinator and delegates SQL to Store.
- Owner-approved native accounting (docs/answers/01-native-usage.md): a Claude/Codex `calls=1` reservation and egress row admit one CLI invocation, potentially containing multiple internal provider requests. New native egress purpose ends with `:cli_invocation`; backend identity also identifies the accounting unit. Failed attempts remain consumed; returned token usage is reported aggregate telemetry, not an exact remaining-quota measure. Jev retains direct per-HTTP-request admission. Native router batches are at most five segments and have no automatic application retries. `max_output_tokens` remains a post-response acceptance threshold for Codex, not a provider generation cap; Claude also enforces its supported per-generation bound. No historical rows or API fields are rewritten.
- Configuration uses JSON syntax in YAML files (a valid YAML subset); no arbitrary YAML tags. Privacy/budget bounds are protected during optimizer runs even though routing.yaml is otherwise mutable.
- Web data, state, selection, keyboard and derived views live under lib; components/pages render markup. Design changes cannot alter lib or generated API.

## Analysis contract (008, owner-added scope)

Frozen types: qualia/core/analysis_models.py. Pure entrypoint `qualia.eval.analysis.analyze(data: dict, options: AnalysisOptions) -> AnalysisReport`; data uses existing workspace source/segment/case/attribute/source_cases/codes/codebook_versions/current_codings tables plus pipeline_version. Reports are read-only and use current assign/accept coding only. Source/case/code any/all/literal query filters intersect; eligible cases are unique links to selected segments (explicit case limits links to that case). Code labels are current display names; version/hash/event identities remain in output. Attribute groups use case attributes only; no source-attribute inheritance. Duplicate equal values collapse, blank-only missing, differing nonblank values conflict. Numeric fields must be explicitly selected, finite decimal/scientific values only; invalid/conflicting and missing counts separate. Pearson n<3/constant=>null. Unicode word counts use each selected segment once, exact casefolded letter/apostrophe tokens, no hidden stopwords/stemming. Result excerpts capped but full totals and contributing segment IDs remain; all percentages have reported denominators. Core rejects unknown filter IDs/attribute names and over-limit input (20000 segments,5000 cases,200 codes; request a smaller imported project if exceeded).

API: authenticated read-only POST `/api/projects/{slug}/analysis` accepts AnalysisOptions and returns AnalysisReport. Read-only POST is chosen for bounded list filters and avoids long encoded URLs. Export POST `/api/projects/{slug}/analysis/export` accepts `{options,format:json|csv|python|r,expected_input_hash?}` and returns existing ExportResult filename/media_type/content. When expected_input_hash is supplied, an input change returns409 before producing content; the UI always sends the displayed report hash. No-text JSON excludes excerpt text/speaker/source_name and words by default; CSV is case-by-code counts plus attribute values, sanitized with column dictionary in JSON. SVG chart export occurs locally in browser; never executes source strings as HTML. CLI `qualia analyze --project SLUG --query TEXT --group-by FIELD --numeric FIELD ... --format json|csv|python|r`, defaultJSONredacted. Static adapter explicitly permits these two analysis POST routes only with exact default options and read-only data; every mutation remains rejected. Snapshot report is optional additive top-level `analysis` and generated from whitelisted selecteddev rows via this same pure function; no backendstatsduplicate. Normal UI can recompute; static controls explain fixed scope.
